# 04 · 运镜：焦段、机位、曲线与抖动

> 运镜不是「让画面动起来」，是**替观众决定看哪里、以什么心情看**。
> 一个镜头只允许一个主运动；第二个运动必须服从第一个。

## 4.1 先定机位，再定运动

新手顺序：想一个帅气的运动 → 找主体 → 画面乱。
正确顺序：

1. **主体在哪**（世界坐标）
2. **观众应该离它多远**（景别）
3. **从哪个方向看**（正面/侧面/俯/仰）
4. **为什么动**（跟随/揭示/压迫/释放）
5. **动多久**（镜头时长）

机位三问：

- 摄影机高度是否低于/等于/高于主体？低于 = 压迫或神圣；等于 = 平等；高于 = 审视或渺小。
- 主体在画面的哪个位置？左/右留白给运动方向。
- 前景有没有东西？没有前景的广角会显得空；有前景的微距会显得深。

## 4.2 焦段与视场

Three.js 的 `PerspectiveCamera.fov` 是**垂直视场角**。2.39:1 画幅下：

```
fov = 2 * atan(sensorHeight / (2 * focalLength)) * 180 / PI
```

以 35mm 全画幅（24mm 高）为参考：

| 焦段 | 垂直 FOV | 观感 | 适合 |
|---|---|---|---|
| 18mm | 67° | 夸张透视、边缘拉伸 | 隧道、坠落、眩晕 |
| 24mm | 53° | 宽广但不失真 | 建立镜头、海面 |
| 35mm | 38° | 自然、接近人眼 | 跟随、环境+主体 |
| 50mm | 27° | 中性、略压缩 | 中景、对话感 |
| 85mm | 16° | 压缩、背景虚化 | 特写、细节、孤立主体 |
| 100mm macro | 13.7° | 极浅景深 | 水珠、纸纤维、火漆 |

**不要**用变焦（fov 变化）代替推轨（位置变化）。变焦改变透视关系，会让观众潜意识不适；
除非你要「眩晕/失控」（dolly zoom）。

2.39:1 的构图注意：

- 水平方向很宽，主体不要永远居中；用左/右三分法。
- 垂直方向很窄，注意头顶/脚下不要切得太紧。
- 字幕区在底部 12%，主体不要压在那里。
- 广角在宽画幅里会显得更空，需要前景或引导线。

## 4.3 运动词汇表

| 运动 | 实现 | 语义 | 注意 |
|---|---|---|---|
| 推（push in） | 位置沿视线前进 | 靠近、揭示、情绪上升 | 速度要慢，加速度要小 |
| 拉（pull out） | 位置后退 | 离开、结束、揭示环境 | 结尾常用，别拉太快 |
| 横移（track） | 位置平行于主体移动 | 陪伴、观察 | 主体速度要匹配 |
| 升降（crane） | 位置垂直移动 | 揭示尺度、命运感 | 起幅/落幅要稳 |
| 环绕（orbit） | 绕主体旋转 | 审视、迷恋、时间流逝 | 别超过 120°，否则会晕 |
| 俯冲（dive） | 快速向前下 | 失控、进入 | 需要运动模糊/粒子 |
| 手持（handheld） | 位置+旋转噪声 | 真实、焦虑 | 幅度小，频率低 |
| 固定（static） | 不动 | 凝视、留白、压迫 | 靠内部事件支撑 |
| 翻滚（roll） | 绕视线旋转 | 失重、梦境 | 全片 ≤2 次 |

**一镜一运动**。如果同时推+摇+滚，观众会不知道自己在哪。允许「主运动 + 微抖动」，
不允许「两个方向相反的主运动」。

## 4.4 曲线机位：关键帧怎么写

推荐用 Catmull-Rom（centripetal）穿过位置关键帧，look 目标单独一条曲线：

```js
const keys = [
  { p: [0, 0.4, 6.0], l: [0, 0.2, 0], fov: 35, roll: 0 },   // 起幅
  { p: [0.6, 0.55, 3.4], l: [0.1, 0.3, 0], fov: 38, roll: -0.01 }, // 中段
  { p: [1.4, 0.8, 1.2], l: [0.2, 0.5, 0], fov: 42, roll: 0 } // 落幅
];
rig.set(keys, { ease: easeInOutCubic, shake: 0.035 });
```

原则：

- **3 个关键帧足够**。5 个以上容易过冲（centripetal 也会在急转弯处甩出去）。
- 起幅和落幅的速度要接近 0（ease in/out）；中段可以匀速。
- look 曲线不要穿过主体（会突然翻转）；让 look 目标始终在主体前方一点。
- fov 变化幅度 ≤ 8°，否则会被感知为「变焦」。
- roll 幅度 ≤ 3°（0.05 rad），除非要失重。

**验证过冲**：采样 100 个点，检查位置曲线是否超出关键帧包围盒 20% 以上；
超出就加关键帧或降低曲率。

## 4.5 缓动

| 缓动 | 用途 | 感觉 |
|---|---|---|
| linear | 机器、传送带、扫描 | 冷、无生命 |
| easeInOutCubic | 大多数镜头 | 自然、有准备 |
| easeOutCubic | 落幅、停止 | 减速、安定 |
| easeInCubic | 起幅、被吸走 | 加速、失控 |
| smootherstep | 极慢的呼吸 | 几乎察觉不到 |

**不要**所有镜头都用同一条缓动。建立镜头用 easeInOut，坠落镜头用 easeIn，
静止镜头用 smootherstep。观众感觉不到曲线，但能感觉到「这个运动有没有生命」。

## 4.6 抖动（handheld / camera shake）

抖动不是随机噪声，是**低频的身体感**。用 3 个不同频率的正弦叠加：

```js
const sx = (sin(t*.73) + .45*sin(t*1.37+1.7) + .16*sin(t*2.11+4.2)) * amp;
const sy = (sin(t*.61+2.2) + .40*sin(t*1.19+5.1)) * amp * .7;
const sz = (sin(t*.47+4.4) + .30*sin(t*1.61+2.3)) * amp * .5;
```

- 幅度：`amp = base * (0.55 + energy * 0.9)`；base 0.02–0.05（世界单位，取决于场景尺度）。
- 频率：0.5–2 Hz，不要超过 3 Hz（会像故障）。
- look 的抖动幅度是位置的 0.5–0.7 倍；roll 抖动 0.002 rad 以内。
- 每个镜头用不同 seed，避免所有镜头同步抖动。
- 固定镜头不要加抖动；呼吸感靠光/粒子/主体微动。

本项目实测：`shake 0.035`、`lookShake 0.02`、`rollShake 0.0018` 在 2–10 单位的场景里
刚好「有生命但不晕」。如果你的场景尺度是 100 单位，按比例放大。

## 4.7 焦点与景深

- 微距镜头必须做景深，否则像贴图。
- 焦点要「拉」而不是「跳」：`focus = lerp(focus, target, 1 - exp(-dt * k))`。
- 焦点转移（rack focus）是一个视觉事件，一个镜头最多一次。
- 广角镜头的景深很深，不要强行加虚化；靠雾/体积光做层次。

Three.js 的 `BokehPass` 或自定义 CoC shader 都可以；注意透明物体与粒子在景深下的排序问题。

## 4.8 运动连续性

切镜时，观众会下意识比较两边的运动：

- **方向连续**：上一镜向右移动，下一镜也从右向左（或保持屏幕方向）。
- **速度连续**：上一镜快速下坠，下一镜不要突然静止；用 0.3 秒的缓冲镜。
- **主体位置连续**：上一镜主体在画面右下，下一镜不要突然跳到左上（除非有意制造断裂）。
- **能量连续**：峰值前的镜头要「加速」，峰值后的镜头要「减速」。

**断裂是工具，不是错误**：在 drop 的瞬间故意反向/静止，能制造冲击。但全片最多 2 次，
且必须登记在分镜的 `event` 里。

## 4.9 常见事故

| 事故 | 原因 | 修法 |
|---|---|---|
| 镜头穿过物体 | 路径没做碰撞/近裁剪面太小 | 近裁剪 0.01–0.05；路径采样 + Raycaster 检测 |
| 主体突然消失 | 被前景遮挡 | 隐藏前景渲染一帧做差分；或抬机位 |
| 画面「翻面」 | look 目标穿过 up 轴 | 限制俯仰 < 85°；用 quaternion lookAt |
| 环绕越转越晕 | 角度 > 180°、半径太小 | 降到 90–120°，半径 ≥ 主体尺寸 2 倍 |
| 运动像电梯 | 只有垂直位移，没有前景 | 加近景元素/粒子/视差 |
| 推轨像变焦 | fov 变化太大 | fov 变化 ≤8°；用位置推 |
| 抖动像地震 | 幅度/频率过高 | 降幅 50%，降频到 1.5Hz |
| 切镜后方向反了 | 没做屏幕方向检查 | 分镜表加 `direction` 字段 |

## 4.10 运镜食谱（按情绪）

| 情绪 | 机位 | 运动 | 焦段 | 时长 |
|---|---|---|---|---|
| 孤独 | 远、低 | 极慢推/固定 | 35–50 | 8–15s |
| 迷恋 | 近、平视 | 缓慢环绕 60° | 85 | 6–10s |
| 压迫 | 低角度、贴近 | 向前推 + 轻微手持 | 24–35 | 3–6s |
| 释放 | 由低到高 | 升降 + 拉远 | 24–35 | 4–8s |
| 失控 | 高角度/翻滚 | 俯冲 + roll | 18–24 | 1.5–3s |
| 神圣 | 低角度、对称 | 固定或极慢上升 | 35–50 | 6–12s |
| 记忆 | 平视、略远 | 横移 + 浅景深 | 50–85 | 5–10s |
| 顿悟 | 从遮挡后出现 | 推 + 焦点转移 | 50–85 | 3–6s |

## 4.11 代码：一个可复用的 CameraRig

完整实现在 `examples/letter-to-the-moon/src/core/camera.js`。核心接口：

```js
const rig = new CameraRig(camera, { shake: .035, seed: 3.1 });
rig.set(keys, { ease: easeInOutCubic });
// 每帧：
rig.update(localProgress, absoluteTime, energy);
```

关键点：

- `localProgress` 必须是**镜头内**进度（0→1），不是全片时间。
- 抖动使用绝对时间，避免切镜时抖动相位重置（会「跳一下」）。
- look 目标加一点「前瞻」：`look += velocity * 0.1`，运动会更自然。
- 切镜时保留 camera 对象，只更新 rig 的 keys；不要每镜 new 一个 camera（会导致后处理失效）。

## 4.13 抄作业：相机与运镜的现成实现

运镜这一层几乎没有「必须自己发明」的东西。下面这些读完就能抄结构，
但**只移植算法，不要把框架拖进成片管线**（渲染必须是纯 `render(t)`）。

| 要做的事 | 项目 | 许可 | 借什么 | 落到本项目的哪里 |
|---|---|---|---|---|
| 参数直觉：焦段/视场/景深 | [three.js examples](https://github.com/mrdoob/three.js/tree/dev/examples)（`webgl_camera`、`webgl_postprocessing_dof`） | MIT | FOV 与距离的换算、CoC 的写法 | `CameraRig` 的 `fov` 关键帧 |
| 弧长参数化的路径 | `THREE.CatmullRomCurve3`（three.js） | MIT | `getPointAt(u)` / `getTangentAt(u)` 匀速采样；`webgl_geometry_extrude_splines` 看曲线编辑 | `src/core/camera.js` 的位置/look 曲线 |
| 阻尼、跟随、边界 | [yomotsu/camera-controls](https://github.com/yomotsu/camera-controls) | MIT | `damp()` 的帧率无关写法、平滑跟随、避免穿墙 | look-dev 交互预览；算法可移植进 `rig.update` |
| 手持抖动 | [pmndrs/drei `CameraShake`](https://github.com/pmndrs/drei) | MIT | 多频噪声叠加 + 衰减的思路 | 4.6 的正弦叠加；不要为了这个引入 R3F |
| 时间点驱动的相机 | [three-story-controls](https://github.com/nytimes/three-story-controls) | MIT | 「story points + 每段缓动」的事件模型 | `keys` 的时间/缓动字段 |
| 可视化调关键帧 | [theatre-js/theatre](https://github.com/theatre-js/theatre)（core） | Apache-2.0（⚠️ Studio 是 AGPL） | 在浏览器里拖关键帧、看曲线，再 bake 成 JSON | look-dev 阶段；Studio 不进成品 |
| 缓动曲线 | [gre/bezier-easing](https://github.com/gre/bezier-easing) | MIT | 自定义 cubic-bezier 求值 | 4.5 的缓动表之外，需要特殊曲线时 |
| 平滑噪声 | [jwagner/simplex-noise.js](https://github.com/jwagner/simplex-noise.js) | MIT | 连续、无周期的漂移 | 焦点漂移、极慢的呼吸感 |
| 景深/运动模糊 | [pmndrs/postprocessing](https://github.com/pmndrs/postprocessing) | Zlib | `DepthOfFieldEffect`、`MotionBlurEffect` 的参数与实现 | 后处理链；或只抄 CoC 公式 |
| 完整作品的相机架构 | [brunosimon/folio-2019](https://github.com/brunosimon/folio-2019) | MIT | 分段相机、滚动驱动、场景切换的组织方式 | 只借结构，不搬资产/文案 |

**移植表**（按这个顺序抄，一天能抄完）：

1. **曲线**：`CatmullRomCurve3(keys, false, 'centripetal', 0.5)`；
   用 `getPointAt` 而不是 `getPoint`，否则关键帧密的地方会变慢。
2. **阻尼**：`x += (target - x) * (1 - Math.exp(-lambda * dt))`。
   `lambda` 越大越跟手；不要再写 `x += (target-x)*0.1`，那个跟帧率绑定。
3. **抖动**：绝对时间 `t` 的多频正弦（4.6），**不要**每帧 `Math.random()`。
   随机数会让两次导出不一样，也会让 24fps 与 30fps 的抖动速度不同。
4. **look 前瞻**：`look = lookCurve.getPointAt(u) + tangent * lookAhead`；
   `lookAhead` 取 0.1–0.3 秒的位移量，转身时才不会「甩头」。
5. **碰撞**：用 `three-mesh-bvh` 从相机向 look 打一条射线，命中就把相机拉近；
   或者简单点，在分镜阶段就把机位画在平面图上人工检查。

**四个不要**：

- 不要把 `OrbitControls` 带进成片。它依赖输入事件，导出时没有输入，且不可复现。
- 不要用物理引擎做运镜。碰撞、弹簧、惯性都不可控，调一次要重渲一遍。
- 不要让相机 `lookAt` 一个正在抖动的目标，抖动会被放大成「点头」。
  先算稳定 look，再加抖动偏移。
- 不要在 `render(t)` 里读 `performance.now()` 或 `deltaTime`。
  所有运动都必须是 `t` 的纯函数。
