# 02 · 音乐地图：把歌变成剪辑网格

> 目标不是「让画面跟着鼓点跳」，而是知道**每一秒音乐在做什么**，从而决定镜头该呼吸还是该冲刺。

## 2.1 三个时间尺度

| 尺度 | 单位 | 用途 | 谁来决定 |
|---|---|---|---|
| 段落（section） | 8–40 秒 | 决定场景、色彩、镜头密度 | 人耳 + 自动边界 |
| 乐句（phrase） | 2–8 秒 | 决定镜头长度、运镜起止 | 人耳 + 波形 |
| 事件（onset/beat） | 0.1–1 秒 | 决定切点、闪烁、粒子爆发 | 自动检测 |

**最常见的错误**：只用第三层。结果每个鼓点都在闪，但整首歌没有结构。

## 2.2 分析管线

```bash
python tools/analyze_audio.py --input public/audio/song.mp3 \
  --out public/analysis --fps 30
```

输出 `analysis.json`：

```json
{
  "duration": 310.16,
  "fps": 30,
  "tempo": 72,
  "bands": { "sub": [...], "low": [...], "midlow": [...], "mid": [...], "high": [...], "air": [...] },
  "rms": [...],
  "vocal": [...],
  "centroid": [...], "flatness": [...], "flux": [...],
  "onsets": [{ "t": 19.1, "s": 1.0 }],
  "sections": [5.0, 19.0, 30.0, 37.5, ...],
  "silences": [[304.97, 310.17]]
}
```

分析器做什么：

1. 解码为 22.05kHz 单声道（分析用，不用于成品）。
2. 30fps 短时傅里叶，计算 6 个频段能量、RMS、频谱质心/平坦度/通量。
3. 人声带 300–3400Hz 能量（近似，不是分离）。
4. Onset：频谱通量峰值 + 局部最大值 + 最小间隔。
5. 段落边界：能量/音色的自相似矩阵 + novelty 峰值（无需预训练模型）。
6. 静音：短时 RMS 低于阈值并持续 >0.3s。

**它不做什么**：不识别和弦、不分离人声、不识别歌词、不给段落命名。
需要更高质量时见 2.8。

## 2.3 先把段落听出来

自动边界只是候选。你必须**完整听一遍**，边听边在纸上记：

```
0:00 墨滴/环境音，无节拍
0:19 第一个低频进入，人声气声
0:31 鼓进入，能量抬升
0:46 副歌？弦乐铺开
1:14 停顿，只剩呼吸
...
5:05 结束，混响尾巴
```

然后把候选边界吸附到**最近的 0.5 秒或最近的 onset**。人耳对 80ms 以内的切点不敏感，
但对「切在半句中间」非常敏感。

段落命名用功能，不用字母：

| 功能名 | 听感 | 典型处理 |
|---|---|---|
| intro | 无拍/环境 | 1 镜到底，建立母题，片名 |
| verse | 有拍但克制 | 6–12 秒一镜，跟随主体 |
| pre-chorus | 能量上升、和声堆叠 | 镜头变短（4–6 秒），运动加速 |
| chorus | 最满 | 2–4 秒一镜，最大亮度/密度/运动 |
| bridge | 抽离、变调 | 突然静止或尺度突变 |
| drop | 低频冲击 | 冲击前 0.5–1.5 秒近乎静止，冲击时切最亮镜 |
| outro | 余响 | 长镜、拉远、黑场/片尾卡 |

**注意**：不是每首歌都有 drop。抒情歌的峰值往往是「最大声的弦乐」而不是鼓。

## 2.4 从特征到画面参数

不要直接把 RMS 接到缩放上——那是可视化，不是导演。用特征**选择**处理方式：

| 音乐特征 | 判断 | 画面决策 |
|---|---|---|
| RMS 高且持续 | 副歌/高潮 | 镜头变短、亮度提高、粒子变密、允许快速运动 |
| RMS 低但 vocal 高 | 主歌/耳语 | 微距、浅景深、镜头长、运动慢、字幕出现 |
| 频谱质心高 | 明亮/金属 | 冷色高光、锐利反射、小颗粒 |
| 频谱质心低 | 暗/厚重 | 体积感、低对比、慢速大形变 |
| flux 高 | 变化快 | 切点密集、形态突变、故障感 |
| flatness 高 | 噪声/气声 | 颗粒、雾、溶解 |
| 低频（sub）强 | 冲击 | 画面整体位移 1–2px、Bloom 瞬时抬升、黑场闪白（慎用） |
| 静音 | 呼吸 | 停止运动、拉远、留白、字幕停留 |
| 人声进入 | 叙事主体 | 主体居中/近景、字幕起始点对齐 |

参考映射（不是公式，是起点）：

```
cutDensity(段落)  = clamp(0.6 + energy * 2.6, 0.6, 3.2)   # 每秒镜头数
cameraSpeed(镜头)  = 0.4 + energy * 1.4                    # 相对基准速度
bloom(全片)        = 0.18 + chorusEnergy * 0.18            # 只在段落内插值
particleDensity   = base * (0.4 + energy * 1.8)
```

**全片只允许一条能量曲线驱动这些参数**，不要每个场景各写一套。把它放在
`src/core/energy.js`，所有场景读同一个归一化值。

## 2.5 剪辑网格

把段落表扩展成可执行的网格：

| # | 段落 | 入点 | 出点 | 时长 | 能量 0–1 | 镜头数 | 平均镜长 | 转场 | 视觉事件 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | intro | 0.00 | 19.10 | 19.1 | 0.12 | 1 | 19.1 | fade 2.4 | 墨滴→片名 |
| 2 | verse1 | 19.10 | 60.20 | 41.1 | 0.38 | 4 | 10.3 | ink/cut | 信→海→鱼→纸阶 |
| 3 | chorus1 | 60.20 | 104.04 | 43.8 | 0.62 | 4 | 11.0 | ink | 上升→红线 |
| 4 | breath | 104.04 | 110.33 | 6.3 | 0.08 | 1 | 6.3 | dip 1.8 | 静止水滴 |
| 5 | verse2 | 110.33 | 157.0 | 46.7 | 0.44 | 4 | 11.7 | ink | 镜→雨→城 |
| 6 | chorus2 | 157.0 | 205.0 | 48.0 | 0.72 | 5 | 9.6 | cut/ink | 下坠→星空 |
| 7 | bridge | 205.0 | 254.0 | 49.0 | 0.50 | 4 | 12.3 | dip | 门→海面晨光 |
| 8 | final | 254.0 | 310.16 | 56.2 | 0.35→0 | 5 | 11.2 | fade | 月光门→片尾 |

规则：

- **平均镜长与能量成反比**，但不要机械：chorus 里也可以有一个 8 秒长镜，用来「喘口气」。
- 每个段落至少有一个「尺度变化」（微距↔广角），否则会平。
- 段落交界处留 0.4–1.5 秒的转场余量；转场时间算在两镜之内。
- 全片最后 5–8 秒留给片尾卡/黑场，不要卡在最后一个音符上。

## 2.6 切点对齐

切点与音乐事件的对齐率：

```
aligned = 切点中距最近 onset/beat < 80ms 的比例
目标：aligned >= 0.6（抒情歌可 0.4；电子/嘻哈应 >0.8）
```

实现：在分镜阶段就写 `beat` 字段（例如 `chorus-1 beat 3`），
再用脚本检查切点与 `analysis.onsets` 的距离：

```js
const near = onsets.some(o => Math.abs(o.t - cut) < 0.08);
```

`validate-storyboard.mjs` 会同时报告两个指标：

- **onset 对齐率**：切点距最近 onset < 80ms；
- **拍网格对齐率**：按 `analysis.tempo` 建网格，相位只拟合一次，再算切点距最近拍 < 80ms。

抒情/慢歌的鼓点常被 onset 漏检，应以拍网格为准；电子/嘻哈节奏密，以 onset 为准。
本项目实测：onset 42%，72 BPM 拍网格 62%（offset 0.73s）——所以它是一部「跟着拍子走、
但不追每个鼓点」的慢歌。若两个指标都低于 0.4，说明切点是凭感觉放的，回分镜重排。

**在峰值前 1–2 拍切**，不要正好切在峰值上。人眼需要 100–200ms 才能识别新画面，
正好切会让峰值「迟到」。

## 2.7 静音与呼吸

静音不是「没声音」，是**最强的注意力工具**。

- 静音前：把运动降到接近 0，让观众以为片子在停。
- 静音中：只留一个视觉锚点（一滴水、一个光点、一行字），镜头不动或极慢推。
- 静音后：第一个声音必须配一个**尺度突变**（微距→广角，或全黑→全亮）。

参考实现里 `104.04–110.33`（6.3 秒）就是这样的呼吸段：全片唯一一次完全静止，
之后接镜面横移。它让后面的副歌听起来更响。

## 2.8 需要更强分析时

| 需求 | 工具 | 注意 |
|---|---|---|
| 段落/节拍/和弦（SOTA） | [allin1](https://github.com/mir-aidj/all-in-one) | 依赖 NATTEN，Windows 无预编译轮子；建议 Linux/WSL |
| 人声/鼓/贝斯分离 | [Demucs](https://github.com/adefossez/demucs) | MIT；分离后再分析人声带更准 |
| 节拍/起始点 | [librosa](https://github.com/librosa/librosa) | ISC；`beat_track` 在渐变速度上会漂 |
| 和弦/调性 | [Essentia](https://github.com/MTG/essentia) | **AGPL-3.0**，不要并入闭源分发 |
| 可视化检查 | [Sonic Visualiser](https://github.com/sonic-visualiser/sonic-visualiser) | GPL；手动标注段落最可靠 |
| 歌词对齐 | [whisperX](https://github.com/m-bain/whisperX) | 需要单独确认模型许可；对齐结果仍要人工听 |

**不要**用 LLM「听」音频来判断段落——它听不见。用波形、频谱和你的耳朵。

## 2.9 交付给下一阶段

音乐地图的产物只有三样：

1. `analysis.json`（机器读）
2. 段落表（人读，含功能名、能量、事件）
3. 一页「听感笔记」：哪一句让你起鸡皮疙瘩、哪里突然安静、哪里必须切

第 3 样最重要。它决定了分镜的「为什么」，而前两样只决定「什么时候」。
